# 범용 투자보고서 설계

## 목적

최종 투자보고서는 엔진의 작동 방식을 설명하는 문서가 아니라, 독자가 회사의 가치동인과 반증 조건을 따라가며 투자판단을 검증할 수 있는 문서다. 일반 가치평가와 분포형 가치평가는 같은 투자자용 입력 계약을 사용한다. 기업별 문구를 렌더러에 하드코딩하지 않는다.

## 논리 사슬

모든 핵심 투자논리는 다음 다섯 요소를 빠짐없이 연결한다.

1. 관찰된 사실과 원문 근거
2. 그 사실에서 도출한 향후 영업 가정
3. 가정이 매출·이익·현금흐름·자본구조를 거쳐 가치에 미치는 방향
4. 논리를 틀렸다고 판정할 반증 조건
5. 다음 공시에서 확인할 지표

가치범위는 숫자만 제시하지 않는다. 하방·기준·상방 또는 분포 구간이 어떤 사업 조건에서 성립하는지 함께 보여준다. 계산 가능한 민감도는 실제 동결 결과에서 가져오고, 계산하지 못한 사업변수 민감도는 방향과 관찰지표만 표시한다. 계산하지 않은 숫자를 만들어내지 않는다.

## 입력 계약

`declarations/investor_report.yaml`은 모든 공개 투자보고서의 단일 편집 입력이다.

| 입력 | 용도 | 누락 시 처리 |
| --- | --- | --- |
| `conclusion` | 현재가와 핵심 가치동인을 연결한 한 문장 결론 | 발행 차단 |
| `investment_points` | 사실·가정·가치영향·반증조건을 잇는 1~3개 투자논리 | 발행 차단 |
| `valuation_method`·`method_rationale` | 선택한 평가법과 선택 이유 | 발행 차단 |
| `scenario_conditions` | 각 가치 구간이 성립하는 사업 조건 | 발행 차단 |
| `sensitivity_watch` | 사업변수의 상·하방 방향과 다음 확인지표 | 발행 차단 |
| `major_assumptions`·`valuation_exclusions` | 핵심 수치 가정과 의도적으로 제외한 가치 | 발행 차단 |
| `risks`·`conditions` | 논리가 깨지는 조건과 행동 조건 | 발행 차단 |
| `sources` | 사람이 읽을 수 있는 원문명과 직접 링크 | 발행 차단 |

증권사 자료는 목표가뿐 아니라 투자논리, 주요 추정치, 평가방법 공개 여부를 보존한다. 엔진은 내재가치 확정 후에만 이를 읽고, 차이를 단순 평균이 아니라 가정 차이로 설명한다.

## 계산 결과와의 연결

- 일반 가치평가: 시나리오별 주당가치와 실제 `valuation_sensitivity_report`를 사용한다. 재현 가능한 경우 할인율·영구성장률·현금흐름 민감도를 표시한다.
- 분포형 가치평가: P20·P50·P80 또는 허용된 모호성 범위, 곤경·희석 비중, 요구수익률별 진입가격 민감도를 사용한다.
- 두 경로 모두 편집 입력의 사업 민감도와 계산 결과를 구분해 표시한다. 편집 입력은 방향과 확인지표를 설명하고, 엔진 결과만 숫자를 말한다.
- 현재가와 증권사 자료는 가치평가 확정 뒤 비교하며 내재가치 입력으로 역류하지 않는다.

## 보고서 순서

1. 투자판단 요약: 판단, 현재가, 내재가치, 범위, 진입가격, 한 문장 결론
2. 투자논리: 각 논리의 근거, 가치 연결, 반증 조건
3. 가치평가와 민감도: 방법 선택 이유, 시나리오 조건, 계산된 민감도
4. 위험과 판단 변경 조건
5. 증권사·시장 비교: 목표가보다 가정 차이를 우선 설명
6. 원문 자료

인공지능의 역할, 실행 단계, 내부 식별자, 해시, 감사 통과 개수는 투자자 본문에 넣지 않는다. 이 정보는 별도 감사 산출물에만 남긴다.

## 실패 방지 규칙

- 공개 보고서 입력은 일반·분포형 경로 모두 같은 형식 검증을 통과해야 한다.
- 입력이 없거나 불완전하면 엔진 설명을 대신 써주지 않고 발행을 차단한다.
- 증권사 설명 필드는 로딩 과정에서 버리지 않는다.
- 투자자 본문에 내부 평가법 ID, 확률 라우트 ID, 증거 ID, 해시가 나오면 테스트가 실패한다.
- 대표 일반 평가와 대표 분포형 평가를 함께 회귀검증한다.
