# Host judgment recovery

## Purpose and authority

Recoverable early input/interpretation gaps are work for the host model, not a successful valuation and not an instruction to bypass a gate. The canonical runner remains the sole execution authority; the host proposes, validators bind decisions to current evidence, and audit alone permits freeze. No vendor LLM SDK or paid fallback is required by the assisted file-handoff path.

This change addresses a concrete cold-start failure: a consolidated reporting-scope note could explicitly say the group has one reportable segment while a deterministic product-table screen raised a multi-segment alarm before the existing hypothesis/bridge staff ran. Merely adding one synonym to a regular expression would not provide a reusable handoff.

## Contract

The common host-judgment request carries a typed cause, company/date/stage, source and input bindings, allowed actions, the expected response schema, validator identity, permitted write targets, and the supported reentry. Responses are proposal-only and must match the current request hash. They cannot declare PASS, skip a stage, issue a freeze, change original source bytes, or authorize publication.

Semantic scope decisions preserve the original filing. A decision about consolidated reportable scope is distinct from the business's economic activities: one IFRS reporting segment may contain multiple products and cash-flow paths. A parent-only statement cannot prove consolidated single scope, and a product list cannot silently become the IFRS segment list.

## Recovery lifecycle

1. An affected early adapter emits the source-bound judgment request instead of an unstructured terminal explanation alone.
2. In assisted mode the host reads the request and writes the prompt-bound proposal through the existing staff handoff.
3. The decision-specific validator checks identity, original member/archive hashes, source text, scope and allowed action. Invalid or unresolved proposals remain incomplete.
4. A validated pending scope receipt is promoted into the hashed declaration inputs between executions, never by silently mutating inputs during the canonical run.
5. The coordinator re-enters the normal canonical runner. Changed dependent results are recalculated; unchanged research may be reused only when its source/prompt/input versions still match.
6. A completed report still requires the existing full scope, audit/freeze, saved state, versioned report, matching SVGs and immutable-bundle verification.

A handoff is not completion. A bounded retry must not become an endless no-change loop. Retry state is associated with the same gap and input identity rather than reset merely because the host resumes the command.

## Scope limits

The typed handlers implement only the decision kinds supported by their validators. An unregistered evaluator, unresolved source contradiction, permission denial, forged source, or authority violation is not repairable by an LLM's assertion. New reusable capabilities still require the user's applicable implementation authorization. The general recovery ladder is not a blanket permission to invent a proxy or to treat every failure as numerical data missing.

This document does not claim that every company can be valued or that Lunit's final valuation has passed. Actual-company validation evidence and remaining gaps belong in the run's diagnostics, separately from fixture tests.

## Verification requirements

- Trigger a host decision before treating a recoverable consolidated-scope ambiguity as final.
- Accept a current source-bound consolidated single-scope proposal and preserve material business coverage.
- Reject stale requests, wrong companies/periods, altered source hashes, nonexistent quotes, parent-only claims and unsupported actions.
- Preserve existing true multi-segment declarations and their source-bound reconciliation.
- Keep generated receipts in hashed inputs for replay, not trusted hidden output state.
- Keep missing-profile and method-input recovery explicit and prevent stale or incomplete reports from publication.
- Do not classify an earlier nonblocking recovery trace as a final failure when a later verified recovery resolved it.
- Preserve persistent retry limits, unchanged-input deduplication, existing audit/freeze guards and last-good output.
- Run focused tests, then the final functional/audit/OCI regression gates; distinguish fixture completion from live-company completion.
