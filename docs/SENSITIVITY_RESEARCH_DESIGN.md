# 민감도 우선 조사와 신사업 추정 설계

설계 기준: main 245dfb2. 사용자가 승인한 목표는 부족한 정보를 조사·추론으로 보완하고 신사업의 실행 가능성과 투자비를 현금흐름에 반영하는 것이다. 특정 회사의 실시간 가치평가를 완료했다는 문서가 아니다.

## 설계 확정

1. 초기 값이 없으면 필수 누락·사업 실행 병목을 우선 조사한다. 민감도는 미측정으로 남기며 0으로 채우지 않는다.
2. 방어 가능한 범위를 확보하면 동일 모형에 low/base/high를 넣어 절대 가치 변동폭을 측정한다. 음수·0 가치도 포함하고 기준값 0의 변화율은 표시하지 않는다. 결합 변수도 별도 실험한다. 민감도는 조사를 배치하는 내부 실험이며 감사 전 공정가치가 아니다.
3. 조사자는 고정된 작업지시와 입력 fingerprint를 받는다. 결과는 독립 파일로 반환한다. 모델 공급자나 API 키를 의무화하지 않는다. ChatGPT/Claude가 자체 검색 도구로 결과를 작성할 수 있다. 선택적 callable 공급자가 있으면 동일 계약으로 호출한다.
4. 원문 URL·발행/최초확인일·위치·문서 해시·관측값/추정값 구분·판단 요약·반대 근거·폐기 조건·추정 범위를 기록한다. 확률 자신감은 보정확률로 승격하지 않는다.
5. 공시/IR/고객/공급자/인허가 조사 후 증권사에서 단서와 추정 방법을 찾을 수 있다. 검증되지 않은 증권사 영업 추정은 분석자 추정의 보조 근거로만 명시한다. 목표가·현재가·추천등급·목표배수는 입력 금지. URL와 해시는 원문 진실성의 자동 인증이 아니다.
6. 신사업은 계약의 매출 전환과 실제 공급 가능량 중 제약을 반영하고, 영업비·세금·설비투자·운전자본을 차감한다. 백로그를 별도 자산으로 더하지 않는다. 잔여 현금흐름, 자금조달, 희석을 생략한 결과를 최종 주주가치로 표시하지 않는다.
7. 조사 작업은 DAG와 읽기/쓰기 경계에 따라 병렬 실행한다. canonical ledger 및 underwriting 반입은 단일 소유자가 한다. 입력 및 의존 결과 해시가 동일한 작업만 재사용하고 변경된 작업과 자손만 재실행한다. 코드/정책/대상/기준일 변화도 fingerprint에 포함한다.
8. 수집/추론의 재사용과 감사 생략은 다르다. 최종 결과는 기존 Compiler→Evaluator→Audit→Freeze를 통과한다. stage 배열을 잘라 이전 승인 결과를 재사용하지 않는다. 기존 KR runner는 KR adapter이며 미국 회사에 사용했다고 주장하지 않는다.
9. 보완 결과가 아직 없으면 재개 가능한 작업지시를 내보낸다. 같은 실패 답변 반복이나 무근거 숫자로 완료하지 않는다. 형식 수정 횟수와 증거 조사 횟수는 별도 제한한다.

## 작업 경계

| 작업 | 단독 쓰기 | 의존성 | 수용 기준 |
|---|---|---|---|
| A 민감도/조사 DAG | research_sensitivity.py, research_task_execution.py 및 전용 테스트 | 이 설계 | 미측정/음수 가치, 결합 실험, 선택 재실행, 병렬 충돌 검사 |
| B LLM 응답 복구 | staff_transport.py, run_kr_live.py, 전용 테스트 | 이 설계 | replay/assisted/live 구분, 새 요청 해시, 소진 시 실제 보완 요청 |
| C 신사업 경로 | new_business_research.py 및 전용 테스트 | 이 설계 | 계약/용량 제약, 지연·CAPEX 변화가 실제 FCFF에 전달 |
| D 조사 반입/통합 | research_campaign.py, run_research_campaign.py, 문서·통합 테스트 | A/B/C 공개 인터페이스 | 답변→추정 반입→기존 컴파일/가치 계산, 재사용/무효화 |

상호 독립 A/B/C 개발 후 D 통합. 공유 계약 변경은 주 담당이 조정한다. 기존 실행과 결과는 기본 설정에서 유지한다.

## 기대효과와 측정

- 자료 부족으로 즉시 끝나는 대신 필요한 조사와 재개 위치가 남는다.
- 회사의 과거 실적 범위를 넘어서는 신사업 경로를 근거 있는 가정으로 수치화한다.
- 조사 순위를 가치 변동폭에 따라 갱신한다. 정확도 향상률은 사전 보장하지 않는다.
- 동일 응답 재투입 때 조사 실행 횟수 0, 한 branch 수정 때 독립 branch 실행 횟수 0을 테스트한다.
- 모형의 가격·기간·CAPEX 변경이 FCFF 및 기존 DCF 결과를 예상 방향으로 변화시키는지 확인한다.
- 현재가·목표가 유입, 오래된 응답, 충돌 입력, 미완료 결과의 완료 승격은 실패해야 한다.

설계 완성 판정: 코드 검토에서 초기 민감도의 순환 의존과 기존 연구 복구의 누락을 확인했고, 위 경로로 해결할 구현 경계와 관측 가능한 수용 기준을 정했다. 기능 달성은 검증 가능하지만 투자 예측 정확도는 동시점 자료를 고정한 사례 및 사후 실적으로 별도 평가해야 한다.
