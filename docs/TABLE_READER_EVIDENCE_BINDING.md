# 표 판독 증거 결박

PR #173의 후속 구현. 2026-09-05 사용자가 Claude 작업을 Codex에 인계했다.

LLM은 공시 표의 의미와 좌표를 제안한다. 검증기는 원문에서 좌표를 확인하고
단위·기간을 검증한다. 기존 Evidence 및 단위 변환 경로를 재사용한다.

## 변경과 검증

| 작업 | 쓰기 범위 | 완료 조건 |
| --- | --- | --- |
| 좌표 증거 | filing_table_cells.py, dart_kpi.py 및 관련 테스트 | 원문·좌표·판독 계약을 저장하고 재검증; 중복 표에서 다른 위치 결박 금지 |
| 장애 구분 | kr_filing_kpi_collector.py 및 관련 테스트 | 통신 실패와 검증기 오류를 미관측으로 삼키지 않음 |
| 준비된 실행 | run_kr_live.py 및 관련 테스트 | 누락된 staff 응답은 명시적인 transport 오류 |
| 통합 | 작업 claim 및 이 문서 | focused 검사 후 전체 회귀, 보고서와 Sanil 실행 검증 |

앞의 세 작업은 서로 다른 파일을 수정하며, 통합 검증은 모두 끝난 뒤 실행한다.
후속 공시 수집 및 작업 claim 보정은 별도 브랜치에서 처리한다.

## 해석 경계

- 모델의 `not_found`는 공시 부재의 증명이 아니다. 관측되지 않았다는 뜻이다.
- 잘못된 좌표는 채택하지 않는다. 통신·검증기 장애는 별도로 드러내야 한다.
- 표 판독 전용 metric은 판독 역할이 준비되었거나 저장 receipt가 있을 때 수집
  capability에 포함한다. 기존 prepared run에 없는 새 역할을 묵시적으로 요구하지 않는다.
  실제 요청한 판독의 실패는 그대로 차단하며, 미공시 응답으로 바꾸지 않는다.
- receipt의 해시는 변경 감지용이다. 원문 진위나 경제적 해석의 정당성을 혼자 증명하지 않는다.
- 재생은 원문과 판독 계약을 다시 검사한다. receipt에 적힌 숫자를 그대로 신뢰하지 않는다.
- 기존 선언 파일 기반 재생과 Evidence hash-chain을 보존한다.
- `declarations/table_cell_receipts.json`은 metric을 저장 receipt JSON에 연결한다.
  준비된 실행은 이 파일을 입력 hash에 포함하고, 신규 추출보다 먼저 재검증한다.
  출력의 Evidence notes에 보존된 receipt를 사용하며, mutable out 파일은 자동 채택하지 않는다.

## 초기 검토 정정

수집 스크립트로 임의 공시를 보관할 수 있다는 사실만으로 미래 공시가 가치평가에
유입된다고 단정할 수 없다. 실행 시 target/as_of 선택 게이트까지 확인해야 한다.
또한 작업 claim의 수동 종료는 기존 명시적 계약이다. 자동 종료 기능의 부재 자체를
P1 결함으로 취급하지 않는다. 실제 우회 경로와 운영 편의 개선을 구분한다.
